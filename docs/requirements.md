# Qwopus-Agent 产品需求

> 状态：当前需求基线
> 适用版本：Milestone 1 当前主分支
> 目的：统一产品目标、用户用例、功能边界和验收标准。技术实现细节见
> [architecture.md](architecture.md)。

## 1. 产品定位

Qwopus-Agent 是一个本地优先、模型无关、可扩展的 AI Agent 系统。它不是只把消息转发
给大模型的聊天界面，而是通过规划、工具调用、文档处理、持久知识、受控研究、
Multi-Agent 协作、报告生成和可复用 Skill，帮助用户完成可追踪的复杂任务。

系统应优先满足以下目标：

1. 用户可以更换模型，而不需要修改 Agent 业务代码。
2. Planner 只负责理解任务和制定计划，Executor 只负责执行已确定的计划。
3. 每项能力以独立 Skill 提供，并由 Registry 自动发现。
4. 原始文档和表格尽量在本地处理，只把有界上下文和计算结果交给模型。
5. 用户只看到最终答案；Tool Observation、原始模型输出和调试轨迹进入主机调试台。
6. 聊天、文件和知识默认按账号及会话隔离，只有显式授权时才扩大访问范围。
7. 弱模型格式不稳定时，系统应安全降级，而不是泄露中间输出或伪造证据。

## 3. 用户与角色

### 3.1 普通成员

普通成员使用正式 Web 界面完成聊天、上传和分析文件、查询自己可访问的知识、生成报告，
以及继续参与别人分享给自己的聊天。

普通成员只能访问：

- 自己创建的聊天、文件、报告和账号全局知识；
- 其他用户明确分享给自己的完整聊天及该聊天附带的文件和报告；
- 当前聊天明确授权使用的 Web、Browser 和 Knowledge 能力。

### 3.2 聊天所有者

聊天所有者除普通成员能力外，还可以：

- 删除自己的聊天；
- 将聊天分享给其他本地账号；
- 撤销分享；
- 决定该聊天上传的文件可被哪些聊天成员访问。

### 3.3 管理员

管理员负责本地安装的运行管理：

- 创建、停用和恢复账号；
- 修改模型连接方式；
- 查看和管理 Skill 候选、版本、推广和回滚；
- 在本机回环地址访问全账号 Debug Console。

管理员不会因为角色本身自动获得其他账号私有聊天的普通 API 访问权。

### 3.4 主机维护者

主机维护者拥有操作系统和项目目录权限，负责：

- 安装 Python、Node、MinerU、MiniRAG 和本地模型依赖；
- 启停 FastAPI、模型服务和可选浏览器依赖；
- 保护 `.env`、Tavily 密钥、本地文件和备份；
- 决定是否把主应用暴露到可信局域网。

主机维护者属于受信任的本地安全边界。

### 3.5 外部系统

| 系统 | 作用 | 数据边界 |
| --- | --- | --- |
| OpenAI-compatible 模型端点 | 规划辅助、证据整理、综合回答和图谱抽取 | 接收本轮发送的提示与有界上下文 |
| MLX `mlx_lm.server` | Apple Silicon 本地模型运行时 | 模型和推理保留在本机 |
| Tavily | 可选实时联网搜索 | 仅在用户启用 Web 时接收搜索查询 |
| Playwright 浏览器 | 可选读取公开网页的渲染内容 | 不复用用户个人浏览器会话 |
| MinerU | 文档版面解析和图片 OCR | 默认作为本地解析流水线 |
| MiniRAG / NanoVectorDB | 持久向量知识存储 | 位于本地 `storage/minirag/` |

## 4. 核心用户用例

### UC-01 初始化账号并登录

**参与者：** 首位管理员、成员
**状态：** 已实现

主流程：

1. 首次启动且数据库没有账号时，系统显示管理员初始化界面。
2. 用户输入显示名、用户名和密码。
3. 系统保存 Argon2id 密码哈希并创建浏览器会话。
4. 后续用户通过账号密码登录。
5. 成功后只加载该账号拥有或被分享的聊天。

验收条件：

- 不存在默认密码；
- 未认证请求不能访问私有 API；
- 停用账号后已有会话失效，活动任务被取消；
- 密码和会话明文不写入数据库或日志。

### UC-02 创建聊天并获得最终答案

**参与者：** 成员
**状态：** 已实现

主流程：

1. 用户创建或选择聊天并输入问题。
2. Intent Resolver 结合当前任务状态识别请求；真正含糊且无法安全执行时请求澄清。
3. Planner 决定单 Agent 或 Multi-Agent 路线，并生成执行计划。
4. Executor 按计划调用已经授权的 Agent 和 Skill。
5. 证据型 Agent 只返回结构化 EvidencePacket。
6. Reviewer 检查冲突、缺口和无支持断言。
7. Synthesizer 生成唯一的用户可见最终答案。
8. 最终答案和安全引用保存到当前聊天。

验收条件：

- Streamlit 或 React 不直接显示 Tool Observation；
- 上游 Agent 失败时不能把其他中间结果误当作最终答案；
- Agent 未生成 `final_answer` 时必须安全解析、重试或明确失败；
- 用户可以停止正在运行的任务；
- 已完成回答在刷新页面后仍存在。

### UC-03 为单轮聊天授权外部能力

**参与者：** 成员
**状态：** 已实现

用户可以为下一轮分别启用：

- **Web**：允许 Tavily 搜索；
- **Browser**：允许读取选定公开网页的渲染内容；
- **Knowledge**：允许检索当前聊天知识库；
- **Global**：在 Knowledge 已启用时，允许检索当前账号的跨聊天知识；
- **Process**：在正式界面显示安全进度，不显示完整原始轨迹。

用户还可以设置：

- Answer detail：Concise、Balanced、Detailed；
- Interpretation range：Precise、Context、Explore；
- Relevance：本地语义检索最低相关性；
- Limit：本轮最多保留 `1` 到 `20` 个不同证据来源。

验收条件：

- 所有能力默认关闭，Knowledge 和 Global 除外时不得隐式读取文件；
- Global 在 Knowledge 关闭时不可启用；
- 来源上限传递到搜索、检索、证据验证和综合，不只是 UI 截断；
- Browser 不能访问回环、私网或本地文件地址；
- 回答语言根据当前用户输入语言决定，不固定为中文。

### UC-04 上传并分析文档

**参与者：** 成员
**状态：** 已实现，有边界

支持类型：

- PDF；
- DOCX；
- Markdown；
- TXT；
- PNG 和 JPEG；
- CSV、XLSX 和兼容引擎可读取的 XLS。

主流程：

1. 用户一次选择一个或多个文件。
2. API 在解析前执行类型、数量和大小限制。
3. 非结构化文件优先通过 MinerU 转换为 Markdown。
4. PDF 和 DOCX 在 MinerU 不可用时使用确定性本地回退；图片必须使用 MinerU OCR。
5. 系统识别页面、标题、章节和表格，并形成有界切片与层次摘要。
6. 用户选择具体问题、章节或全文分析。
7. 系统显示最终分析结果、来源覆盖和可选报告下载。
8. 上传文件的 Markdown 和安全摘要写入当前会话及账号聚合知识库。

验收条件：

- 不再以“文档前 16000 字符”作为完整分析结果；
- 长文档按结构和标题切分，切片保留文件、章节和页码来源；
- 多文件分析能够区分每个来源，不因同名或重复选择产生歧义；
- 穷尽式多来源任务（要求覆盖全部文件并输出完整报告）由本地 grounded 合成器确定性组装：每个文件是一个独立来源槽位，逐课命名的文件（第N课 / lesson N）按课号排序，经文引用按来源自身允许的卷节范围校验，相邻来源不被合并成一个泛化主题；
- 通用配方覆盖所有文档类型（含圣经查经课文件），不依赖单独的“圣经模式”选择；
- 页面不显示原始 Tool Observation；
- MinerU 或模型失败时给出可行动的错误，不使 API 进程崩溃。

当前边界：

- 图片解析依赖本地 MinerU 模型和 OCR 运行环境；
- PDF/DOCX 回退解析的版面质量低于完整 MinerU；
- 本地目录模式只直接分析选中的原文件，不复制或写入 MiniRAG。

### UC-05 直接分析本地文件夹

**参与者：** 管理员
**状态：** 已实现

主流程：

1. 用户输入本机绝对目录路径。
2. 系统扫描受支持文件并显示树状结构。
3. 用户选择本轮需要分析的具体文件。
4. 系统直接读取并分析所选文件，不自动进入向量库。

验收条件：

- 路径必须位于允许的本地范围；
- 目录树显示文件层级、类型和大小；
- 一次选择数量有明确上限；
- 未选中的文件不会进入模型上下文。

### UC-06 安全分析 Excel 数据

**参与者：** 成员
**状态：** 已实现，有边界

主流程：

1. 系统本地读取工作簿结构、工作表、表格区域、列名、类型和样本行。
2. 整个工作簿不得直接发送给 LLM。
3. LLM 根据 schema 和问题生成受限 pandas 表达式。
4. AST 校验器阻止导入、文件访问、网络、危险内建函数和未知方法。
5. 独立子进程执行表达式，并返回有界 JSON 结果。
6. 模型只基于 schema、样本和本地计算结果生成最终解释。

验收条件：

- 混合类型和空表头不能导致 `select_dtypes` 一类未处理错误；
- 工作簿原始全量数据不进入模型提示；
- 沙箱超时、越权或结果过大时明确拒绝；
- macOS 使用 Seatbelt 进一步禁止网络、写文件和 fork；
- 模型若自算统计值（均值、IQR 离群点数量、p 值、R²）却未调用本地 Skill 工具，运行时本地复算并校验该值：一致则接受并附本地表，不一致或缺失数字则 fail-closed，保证最终统计值可核对；
- `excel_statistics` 覆盖可复核的假设检验与数据整理：单样本 t、Welch 双样本 t、Mann-Whitney U、Wilcoxon 符号秩、Kruskal-Wallis H，以及 pivot、date_extract、deduplicate、rank；
- `excel_modeling` 覆盖二分类逻辑回归（McFadden 伪 R²、系数置信区间、log-odds 单位限制说明），弱模型不能把“逻辑回归”误路由为线性回归。

当前边界：

- 旧 `.xls` 是否可用取决于本地 pandas Excel engine；
- pandas 沙箱是纵深防御，不等同于通用虚拟机；
- 双因素/重复测量 ANOVA、预测区间和多表 merge 不在当前 `excel_statistics`/`excel_modeling` 覆盖内。

### UC-07 使用会话知识和账号全局知识

**参与者：** 成员
**状态：** 已实现，有边界

主流程：

1. 上传文件转换为 Markdown，并按章节生成带来源的切片。
2. MiniRAG 在 `storage/minirag/conversations/<conversation_id>/` 持久化会话知识。
3. 同一内容写入 `storage/minirag/users/<user_id>/` 的账号聚合。
4. 默认只搜索当前聊天。
5. 用户显式启用 Global 后，才补充搜索当前账号聚合。
6. 检索融合本地向量结果和有证据约束的知识图谱路径。

验收条件：

- 重启应用后索引自动加载；
- 会话 A 默认不能检索会话 B 的文件；
- 账号 A 不能检索账号 B 的全局知识；
- 图谱实体、关系和路径必须保留支持它们的来源片段；
- 删除或更新文档时同步维护 JSONL、向量和图谱派生数据。

当前边界：

- Qwopus 使用上游 MiniRAG 的持久 NanoVectorDB 组件，但拥有自己的切片、权限、
  检索融合和图谱流程；它不暴露完整的上游 `MiniRAG.query`；
- 本地嵌入模型与聊天模型独立；
- 低相关性阈值可能引入无关来源，来源数量上限不能代替相关性控制。

### UC-08 分享聊天及其文件

**参与者：** 聊天所有者、被分享成员
**状态：** 已实现

主流程：

1. 所有者输入另一个本地账号的准确用户名。
2. 系统为整个聊天创建成员授权。
3. 被分享成员可以阅读和继续聊天，并访问该聊天附带的文件和报告。
4. 所有者撤销成员后，对方立即失去访问，相关活动任务被取消。

验收条件：

- 只有所有者可以分享、撤销、重命名或删除聊天；
- 分享不会授权所有者的其他聊天或账号全局知识；
- 管理员不会通过普通 API 自动绕过聊天 ACL。

### UC-09 生成并下载报告

**参与者：** 成员
**状态：** 已实现

ReportGenerator 从统一请求生成：

- Markdown；
- Excel；
- PNG/SVG 图表；
- 支持 Unicode 和分页的 PDF。

验收条件：

- 所有格式由同一业务模块生成；
- 图表是实际图片，不是 manifest 占位；
- 报告文件遵守账号和共享聊天权限；
- 报告正文不得包含“略”“待补充”等遗漏占位。

### UC-10 更换模型

**参与者：** 管理员
**状态：** 已实现，有边界

主流程：

1. 管理员选择远程 OpenAI-compatible 地址，或提交本地 MLX 模型目录。
2. 后端验证连接或目录。
3. 每次运行前通过 `/v1/models` 刷新当前模型标识。
4. Planner、Executor、Skill 和 Memory 只依赖统一 LLM 合同。

验收条件：

- UI 修改运行时设置时不改写 `.env`；
- 模型名称不能硬编码为 Gemma、Qwen 或其他固定名称；
- 本地 MLX 子进程随应用生命周期正确启动和停止；
- 不支持结构化输出的弱模型仍能通过有界解析和回退完成安全任务。

当前边界：

- “任意模型”表示兼容 OpenAI API 行为，或已经提供 `BaseLLM` 适配器的模型；
- 完全不同协议的模型仍需要新增适配器；
- 模型能力不足可能降低图谱抽取、规划和综合质量，但不能突破权限和验证边界。

### UC-11 Multi-Agent 协作

**参与者：** 成员、系统
**状态：** 已实现

复杂任务可以使用：

- Supervisor；
- 任务委派和依赖 DAG；
- 独立任务并行执行；
- 共享的受控状态；
- 证据审查与冲突标记；
- 一次有明确缺口的 gap-fill；
- Synthesizer 最终综合；
- 确定性仲裁与终态所有权。

验收条件：

- 失败依赖向下传播，但不能被误判为依赖循环；
- 真正的循环依赖必须在执行前拒绝；
- 并行任务不能覆盖彼此结果；
- 只有规划指定的成功 terminal task 可以拥有最终答案；
- 中间 Agent 不直接写入用户消息。

### UC-12 Skill 自动发现、成长和推广

**参与者：** 管理员、系统
**状态：** 已实现，有边界

主流程：

1. Registry 自动扫描 `skills/` 中实现统一工厂合同的模块。
2. 重复成功的安全工作流可以形成声明式 Workflow Skill 候选。
3. 管理员也可以指定一次聊天中的成功运行，或描述目标并限定可用能力，要求模型生成候选。
4. Pydantic、checksum、版本差异和无副作用 dry run 验证候选。
5. 管理员手动 Promote、Reject 或 Rollback。

验收条件：

- 添加内置 Skill 不需要修改中央注册列表；
- 候选不能携带凭据、任意文件路径、未知能力或任意 Python；
- 自动观察不会直接部署新 Skill；
- 活动任务固定使用启动时的已验证 Skill 版本。

当前边界：

- 自动成长只生成受限声明式工作流；
- 任意模型生成代码并自动部署不在当前安全范围；
- 推广始终需要管理员确认。

### UC-13 主机调试与审计

**参与者：** 本机管理员
**状态：** 已实现

Debug Console 显示：

- 当前模型、端点、运行模式、平台和任务数量；
- 账号、会话、运行状态和完整编排事件；
- 记录到的提示、模型输出、Tool 调用、Observation 和解析错误；
- Skill 候选生成、验证、测试和生命周期；
- 有界运行日志。

验收条件：

- `/debug` 和 Debug API 只允许回环地址加管理员会话；
- 局域网客户端不能通过环境变量打开 Debug；
- 正式聊天界面不能显示这些原始数据；
- 调试记录包含发起任务的账号，方便主机审计。

## 6. 非功能需求

### NFR-01 可维护性

- Python 3.11 类型完整；
- 请求和跨边界数据使用 Pydantic 或明确 typed contract；
- 业务逻辑位于 Agent、Service、Skill、Memory 和 Report 模块，不进入 React 或 API 路由；
- 模块依赖遵守 UI/API → Service → Domain contract → Provider 的方向；
- 非显然代码需要解释“为什么存在”和“起什么作用”的注释。

### NFR-02 可测试性

- 每个模块可以注入模型、知识库、搜索和文件依赖；
- 每次功能修改至少运行相关单元测试；
- 跨模块或安全边界修改运行完整测试；
- 文档、Excel、MiniRAG、报告和 Agent 关键流程保留真实格式或真实服务用例；
- 前端修改通过 TypeScript、ESLint、生产构建和桌面/移动布局检查。

### NFR-03 性能

- 首屏不需要的 Documents、Skills、Dialog 和 Inspector 使用延迟加载；
- 长任务在独立进程运行，UI 可以轮询并取消；
- 文档和证据使用 token budget，不把完整大文件送给模型；
- 可独立任务并行执行，依赖任务按 DAG 顺序执行；
- 用户可调来源数量，避免弱模型被过大上下文拖慢。

### NFR-04 可靠性

- 模型、MinerU、Tavily 或 Browser 失败不能使 FastAPI 主进程退出；
- 后台任务异常退出后返回明确终态；
- 写入知识、调试记录和报告时使用可恢复或原子边界；
- 重启后聊天、文档、知识、Skill 和报告索引可恢复。

### NFR-05 安全与隐私

- 默认本地存储；
- 外部模型和 Tavily 只在相应能力被使用时接收必要数据；
- 不把密钥写入 Git、提示、Skill 或调试输出；
- Browser 阻止 SSRF 和本地网络访问；
- pandas 代码在受限子进程执行；
- 正式 UI 不展示原始推理、Observation 或跨账号调试内容。

### NFR-06 可用性

- UI 提供聊天、文档和 Skill 清晰分区；
- 不熟悉的控制有延迟悬停说明；
- 长答案、表格、代码、来源和输入区不能互相覆盖；
- 用户可以明确看到运行进度、失败原因、模型在线状态和可下载报告；
- 用户输入语言决定最终回答语言。

## 8. 当前不在范围

- 不受限制地生成、执行并自动部署任意 Python Skill；
- 使用个人浏览器登录态执行购物、支付或账户操作；
- 外部 OAuth、企业 SSO、跨安装组织租户和字段级权限；
- 操作系统层面的每账号磁盘加密；
- 将完整上游 MiniRAG 查询引擎直接暴露给 Agent；
- 保证任何未知协议、未知上下文格式的模型可以零适配接入；
- 无人审查的全自动 Skill 推广；
- 把隐藏的模型内部思维链展示给用户。

## 9. 后续需求优先级

### P0：稳定现有能力

1. 为真实远程模型运行增加明确的阶段超时和耗时指标。
2. 持续评估弱模型在 EvidencePacket、图谱 JSON 和 final answer 格式上的成功率。
3. 增加大文件、多语言、多表格和扫描图片的固定真实案例集合。
4. 为 MiniRAG 相关性、来源覆盖和错误引用建立可量化回归集。

### P1：提升回答质量和可观察性

1. 让用户在回答中查看结构化引用详情，但仍不暴露 Tool Observation。
2. 在 Debug Console 对每个 Agent 阶段显示 token、耗时、重试和失败分类。
3. 为 Detailed 模式建立任务类型相关的深度评分，而不是固定长度要求。
4. 为跨文档冲突、时间有效性和来源权威性增加更明确的审查信号。

### P2：扩展能力

1. 根据真实使用数据决定是否增加新的模型协议适配器。
2. 在安全边界明确后扩展只读浏览器操作类型。
3. 增加知识图谱可视化和用户可检查的实体合并/拆分。
4. 扩展 Skill 候选的离线评测集和灰度启用机制。
